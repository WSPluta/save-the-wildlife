## Core Objective

Create secure, accurate, repository-grounded content tailored to a publishing platform without drifting from Oracle AI Database branding.

## Universal Rules

- Use repository reality, not imagined architecture.
- Replace secrets with placeholders.
- Include repo links, use cases, and a disclaimer where appropriate.
- Keep code samples annotated enough that a reader can follow the flow.

## Platform Guidance

### Medium

- Narrative and thought-leadership heavy
- Best for why-it-matters framing, real-world context, and future implications

### dev.to

- Code-forward and peer-to-peer
- Best for architecture diagrams, implementation snippets, gotchas, and operational practices

### DataCamp

- Step-by-step and educational
- Best for guided learning, prerequisites, numbered exercises, and progressive concepts

## Structure Expectations

- Medium: Hook, story, problem, solution, implications
- dev.to: Problem, architecture, code, gotchas, practices, resources
- DataCamp: Goals, prerequisites, concepts, steps, wrap-up

## LLM-Friendly Content Patterns

- Use Mermaid for architecture when it adds clarity.
- Favor numbered flows, Q&A blocks, and annotated snippets.
- Use realistic JSON placeholders and configuration examples.

## Validation

- Branding is correct.
- The content matches the selected platform.
- Snippets and diagrams reflect the repo.
- No secrets or misleading shortcuts appear.
