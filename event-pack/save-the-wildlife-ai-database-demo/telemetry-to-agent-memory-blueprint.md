# Save the Wildlife: Telemetry To Agent Memory Blueprint

## One-Line Narrative

The game is the toy. The production pattern is that real-time application telemetry becomes the memory, context, evaluation, and learning loop for bounded AI agents on Oracle AI Database and OCI.

## What This Demo Proves

Save the Wildlife is not an "LLM watches a screen" demo. The agent does not infer gameplay from pixels. It consumes deterministic application primitives: player movement, trash collection, powerups, trail crossings, freeze events, marine hits, scores, coordinates, and replay clip metadata.

That matters for AI engineers because it turns agent behavior into a systems problem:

- facts are stored as database evidence
- context is retrieved from known schemas
- generation is bounded by SQL, JSON, graph, replay, and memory records
- model output is traced, evaluated, and exported for continuous improvement
- deployment stays inside OCI, with Oracle AI Database, PAF, OKE, and OCI DevOps forming the loop

## The Implemented Data Spine

The current repo uses `STWL_*` objects as the concrete memory core. Treat `oracleagentmemory` as the architectural pattern: structured events become memory primitives that can be summarized, retrieved, compared, evaluated, and fed into agent workflows.

The implemented core ledger is `STWL_GAME_EVENTS`:

```sql
CREATE TABLE stwl_game_events (
  id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id VARCHAR2(128) NOT NULL,
  room_id VARCHAR2(64) NOT NULL,
  player_id VARCHAR2(128) NOT NULL,
  player_name VARCHAR2(256),
  event_type VARCHAR2(40) NOT NULL,
  occurred_at TIMESTAMP WITH TIME ZONE NOT NULL,
  score NUMBER,
  x NUMBER,
  y NUMBER,
  z NUMBER,
  related_player_id VARCHAR2(128),
  related_item_id VARCHAR2(128),
  metadata_json CLOB CHECK (metadata_json IS JSON)
);
```

Supported event types:

- `game_started`
- `position_sample`
- `trash_collected`
- `marine_hit`
- `powerup_collected`
- `trail_crossed`
- `player_frozen`
- `game_over`

Example event:

## Physical Landing Path

The browser emits gameplay evidence through the existing Socket.IO flow. The server normalizes and persists that event through `server/lib/gameEvents.js`.

```js
export async function recordGameEvent(payload, context = {}) {
  const event = normalizeGameEvent(payload, context);
  if (shouldDropSample(event)) return { ok: true, skipped: true, event };

  rememberLocal(event);

  let persisted = false;
  try {
    persisted = await persistService(event);
    if (!persisted) persisted = await persistOracle(event);
  } catch (error) {
    return { ok: true, persisted: false, event, warning: error.message };
  }

  return { ok: true, persisted, event };
}
```

The Oracle insert is explicit and deterministic:

```sql
INSERT INTO stwl_game_events (
  id, session_id, room_id, player_id, player_name, event_type, occurred_at,
  score, x, y, z, related_player_id, related_item_id, metadata_json
) VALUES (
  stwl_game_events_seq.NEXTVAL,
  :session_id, :room_id, :player_id, :player_name, :event_type,
  TO_TIMESTAMP_TZ(:occurred_at, 'YYYY-MM-DD"T"HH24:MI:SS.FF3"Z"'),
  :score, :x, :y, :z, :related_player_id, :related_item_id, :metadata_json
);
```

This is the key technical point: the agent is grounded in committed gameplay facts, not free-form logs or hidden model state.

## Converged Oracle AI Database Layout

The schema is production-shaped even though the demo is small.

| Layer | Implemented Object | Purpose |
| --- | --- | --- |
| SQL event ledger | `STWL_GAME_EVENTS` | Authoritative match facts |
| Session summary | `STWL_SESSION_SUMMARY` | Deterministic per-player rollups |
| JSON event documents | `STWL_EVENT_DOCUMENTS` | Agent-friendly document view over telemetry |
| Graph facts | `STWL_GRAPH_VERTICES`, `STWL_GRAPH_EDGES`, `STWL_GAMEPLAY_GRAPH` | Player, item, session, trail, freeze, and causality relationships |
| Replay manifests | `STWL_REPLAY_CLIPS` | Clip URI, thumbnail, event window, replay JSON, tags, moderation status |
| Agent memory | `STWL_AGENT_MEMORIES` | Vector-ready memory cards for similar moments and player/session history |
| Model traces | `STWL_MODEL_TRACES` | Prompt, evidence, route, provider, and hash records |
| Model outputs | `STWL_MODEL_OUTPUTS` | Base and candidate model responses |
| Evals | `STWL_MODEL_EVALS` | Rubric outcomes and scoring |
| Training examples | `STWL_TRAINING_EXAMPLES` | Accepted examples for future adaptation or fine-tuning |
| Promotions | `STWL_MODEL_PROMOTIONS` | Candidate model or adapter promotion decisions |

## Telemetry To Context Card

PAF and the in-database package do not need a raw event dump. They build a compact context card from evidence:

- latest score
- trash collected
- marine hits
- powerups by type
- trail crossings
- freeze count
- last known coordinates
- prior best score when history exists
- replay clips when available
- graph facts when available
- vector memory when available

The in-database entry point is `STWL_COMMENTARY_PKG.BUILD_SCRIPT_JSON`.

```sql
FUNCTION build_script_json(
  p_session_id         IN VARCHAR2,
  p_player_id          IN VARCHAR2,
  p_max_chars          IN NUMBER   DEFAULT 200,
  p_select_ai_profile  IN VARCHAR2 DEFAULT 'STWL_GAMEPLAY_AI',
  p_agent_team_name    IN VARCHAR2 DEFAULT NULL
) RETURN CLOB;
```

Its generation path is deliberately bounded:

1. Build SQL summary JSON from `STWL_GAME_EVENTS`.
2. Try `DBMS_CLOUD_AI_AGENT.RUN_TEAM` when an in-database agent team is configured.
3. Try `DBMS_CLOUD_AI.GENERATE` through Select AI profile `STWL_GAMEPLAY_AI`.
4. Fall back to deterministic SQL commentary.
5. Clamp to conference-safe text under the configured character limit.

## PAF Runtime Contract

The PAF service is the agent workflow surface. It receives a session/player request, gathers database-backed evidence, and returns one of four formats:

- `live_line`
- `replay_caption`
- `post_match_recap`
- `clip_title`

Runtime prompt contract:

```text
Use only this SQL gameplay telemetry and the optional Oracle AI Database draft.
Do not invent events, animals, players, or history.
Return one profanity-free commentator line under 200 characters.
Mention powerups, trail crossing/freezing, coordinates, or prior best only when present.
Mention replay clips only when replay_evidence is not none.
```

That is the anti-hallucination story. The model is allowed to phrase. The database decides what happened.

## Select AI Angle

Select AI is the developer-facing bridge between natural language and gameplay telemetry.

Use it for demo exploration:

```sql
SELECT DBMS_CLOUD_AI.GENERATE(
  prompt       => 'Which player collected a freeze powerup and later crossed another player trail?',
  profile_name => 'STWL_GAMEPLAY_AI',
  action       => 'showsql'
) AS generated_sql;
```

Use explicit SQL and bounded package calls for the runtime commentary path. This keeps the live demo deterministic while still proving natural language over the same telemetry store.

## Continuous OCI DevOps Flywheel

The learning loop is where the story becomes Software 2.0.

1. Gameplay creates evidence in `STWL_GAME_EVENTS`.
2. PAF builds prompts and evidence cards.
3. Base and candidate model outputs are stored in `STWL_MODEL_OUTPUTS`.
4. Rubrics write outcomes to `STWL_MODEL_EVALS`.
5. Accepted traces become `STWL_TRAINING_EXAMPLES`.
6. `private-agent-factory/scripts/export-training-examples.mjs` exports JSONL records.
7. OCI DevOps can package, test, and redeploy prompt policy, model routing, or fine-tuned adapters.

Export shape:

```json
{
  "trace_id": "stwl-room0001-a1b2c3d4",
  "session_id": "ROOM-0001:user-402",
  "player_id": "user-402",
  "prompt_hash": "evidence-boundary-hash",
  "evidence_hash": "sql-json-graph-replay-hash",
  "prompt_text": "Produce one concise Save the Wildlife commentary line using only Oracle AI Database evidence references.",
  "citations": [
    "STWL_GAME_EVENTS:ROOM-0001:user-402",
    "STWL_MODEL_TRACES:stwl-room0001-a1b2c3d4"
  ],
  "output_text": "Magnet pickup into a clean streak: User 402 turned telemetry into scoreboard pressure."
}
```

This is the Agent IP Store argument: the valuable asset is not just the model. It is the secured corpus of traces, evidence cards, evals, policies, and accepted examples.

## Production Interpretation

Demo scale:

- web game on OKE
- Socket.IO event stream
- Oracle AI Database telemetry ledger
- PAF commentary service
- Select AI exploration
- model traces and training export

Production scale:

- Unity, Unreal, mobile, web, or backend game SDK emits normalized telemetry
- replay clips are stored in object storage and indexed by match, timecode, player, event, and moderation status
- graph explains player-versus-player and player-versus-item causality
- vector memory retrieves similar prior moments and player style
- PAF or an agent harness orchestrates context, policy, evaluation, and model routing
- OCI DevOps promotes prompts, adapters, model routes, and service changes under governance

## What To Say On Stage

"The game is not the point. The game is the event engine.

Every movement, pickup, powerup, collision, freeze, and replay marker lands as evidence in Oracle AI Database. From there, SQL gives us facts, JSON gives us documents, graph gives us causality, vectors give us memory, and PAF gives us the agent workflow.

The model is not asked to remember the game. It is asked to speak from the evidence. That is the difference between an AI wrapper and a production agent system.

Then OCI DevOps closes the loop. We can evaluate the commentary, keep the good traces, reject the bad ones, export training examples, and redeploy improved behavior without moving the agent IP outside the OCI boundary."

## Claims To Avoid

Do not claim the current game backend imports `oracleagentmemory.core.OracleAgentMemory` unless that library is actually wired into the runtime.

Do not claim the deployed model is `xai.grok-3-fast` unless the environment and PAF health output prove that exact model route.

Do not use non-game animals such as moose in examples. The implemented game evidence is trash, turtles/marine life, powerups, trail crossings, freezes, boats, coordinates, replay clips, scores, and players.

Do not imply hallucination is impossible. Say the runtime is evidence-bounded, constrained, clamped, profanity-guarded, and evaluated.

## Closing Line

The game is the trojan horse. The real story is that Oracle AI Database gives agents a memory core, PAF gives developers a factory, and OCI gives the whole loop a production runtime.
